# Architectures Reference

## Design Summary

VM counts and host groups verified directly against `themis/scripts/generate_inventory.py`
and `themis/vms/aws/tfvars/*.tfvars` (2026-09-13). Gateway VMs are now included in all
four architectures' base tfvars. `generate_inventory.py` creates a `gateway` group only
for ASA — for AIO/Minimal/HA2, `scripts/fix_gateway_group.py` adds it automatically.

| Design | VMs (base tfvars) | of which gateway | Use Case |
|--------|-------------------|------------------|----------|
| `aio` | 1 | 0 (colocated — no extra VM) | POC / dev / testing |
| `minimal` | 4 | 1 | Small deployments |
| `ha2` | 9 | 1 | Production HA |
| `asa` | 17 | 2 | Active-Standby dual-site |

---

## AIO (All-In-One)

Single host running everything.

**Instance name:** `all`

**Host groups generated by `gen_aio()`:**
```
redis_master     → all (same host)
mongodb_primary  → all (same host)
platform         → all (same host)
```

**tfvars (`tfvars/aio.tfvars`):**
```hcl
design = "aio"
instances = [
  { name = "all", instance_type = "t3.medium" }
]
```

**Gateway:** no dedicated VM — `fix_gateway_group.py` reuses the single `all` host for the `gateway` group.

---

## Minimal

4 hosts — one Redis, one MongoDB, one Platform, one Gateway.

**Instance names:** `redis`, `mongo`, `platform`, `gateway`

**Host groups generated by `gen_minimal()`:**
```
redis_master     → redis
mongodb_primary  → mongo
platform         → platform (vars: platform_encryption_key, platform_mongo_url, platform_redis_host)
```

`gen_minimal()` does not create a `gateway` group — `fix_gateway_group.py` adds it from the `gateway` instance already in tofu state.

**tfvars (`tfvars/minimal.tfvars`):**
```hcl
design = "minimal"
instances = [
  { name = "redis",    instance_type = "t3.medium" },
  { name = "mongo",    instance_type = "t3.medium" },
  { name = "platform", instance_type = "t3.medium" },
  { name = "gateway",  instance_type = "t3.medium" }
]
```

## HA2 (High Availability)

9 hosts — 3 Redis (with Sentinel), 3 MongoDB replica set, 2 Platform, 1 Gateway.

**Instance names:**
- Redis: `redis01`, `redis02`, `redis03`
- Mongo: `mongo01`, `mongo02`, `mongo03`
- Platform: `platform01`, `platform02`
- Gateway: `gateway`

**Host groups generated by `gen_ha2()`:**
```
redis_master     → redis01
redis_replica    → redis02, redis03
redis_sentinel   → redis01, redis02, redis03
mongodb_primary  → mongo01
mongodb_replica  → mongo02, mongo03
platform         → platform01, platform02
                   (vars: platform_encryption_key, platform_mongo_url, platform_redis_sentinels)
```

`gen_ha2()` does not create a `gateway` group — `fix_gateway_group.py` adds it from the `gateway` instance already in tofu state.

**tfvars (`tfvars/ha2.tfvars`):**
```hcl
design = "ha2"
instances = [
  { name = "platform01", instance_type = "t3.medium" },
  { name = "platform02", instance_type = "t3.medium" },
  { name = "redis01",    instance_type = "t3.medium" },
  { name = "redis02",    instance_type = "t3.medium" },
  { name = "redis03",    instance_type = "t3.medium" },
  { name = "mongo01",    instance_type = "t3.medium" },
  { name = "mongo02",    instance_type = "t3.medium" },
  { name = "mongo03",    instance_type = "t3.medium" },
  { name = "gateway",    instance_type = "t3.medium" }
]
```

## ASA (Active-Standby)

17 hosts — 6 Redis, 5 MongoDB, 4 Platform (split primary/secondary), 2 Gateway.
All instances use flat sequential numbering (no `dc1-`/`dc2-`/`dc3-` prefix).

**Instance names:**
- Redis (primary site): `redis01`, `redis02`, `redis03`
- Redis (secondary site): `redis04`, `redis05`, `redis06`
- MongoDB: `mongo01`, `mongo02`, `mongo03`, `mongo04` (replicas), `mongo05` (arbiter)
- Platform (primary site): `platform01`, `platform02`
- Platform (secondary site): `platform03`, `platform04`
- Gateway: `gateway01`, `gateway02`

**Host groups generated by `gen_asa()`:**
```
redis                → redis01, redis02, redis03
redis_secondary      → redis04, redis05, redis06
mongodb              → mongo01, mongo02, mongo03, mongo04
mongodb_arbiter      → mongo05
platform             → platform01, platform02
                       (vars: platform_encryption_key, platform_mongo_url, platform_redis_sentinels)
platform_secondary   → platform03, platform04
                       (vars: same as platform, using secondary-site redis sentinels)
gateway              → gateway01, gateway02
```

`gen_asa()` **does** create the `gateway` group automatically — no `fix_gateway_group.py` needed for ASA.

**tfvars (`tfvars/asa.tfvars`):**
```hcl
design = "asa"
instances = [
  { name = "platform01", instance_type = "t3.medium" },
  { name = "platform02", instance_type = "t3.medium" },

  { name = "platform04", instance_type = "t3.medium" },
  { name = "redis01",    instance_type = "t3.medium" },
  { name = "redis02",    instance_type = "t3.medium" },
  { name = "redis03",    instance_type = "t3.medium" },
  { name = "redis04",    instance_type = "t3.medium" },
  { name = "redis05",    instance_type = "t3.medium" },
  { name = "redis06",    instance_type = "t3.medium" },
  { name = "mongo01",    instance_type = "t3.medium" },
  { name = "mongo02",    instance_type = "t3.medium" },
  { name = "mongo03",    instance_type = "t3.medium" },
  { name = "mongo04",    instance_type = "t3.medium" },
  { name = "mongo05",    instance_type = "t3.medium" },
  { name = "gateway01",  instance_type = "t3.medium" },
  { name = "gateway02",  instance_type = "t3.medium" }
```

## Gateway Handling

Gateway VMs are included in all four architectures' base Themis tfvars (as of the current main branch).
`generate_inventory.py` creates a `gateway` group automatically only for ASA. For AIO/Minimal/HA2,
`scripts/fix_gateway_group.py` reads tofu state and adds the group:

| Architecture | Gateway VM(s) in tfvars | `gen_*()` creates gateway group? | Fix needed |
|---|---|---|---|
| `aio` | None | No | `fix_gateway_group.py` reuses `all` host |
| `minimal` | `gateway` | No | `fix_gateway_group.py` adds from tofu state |
| `ha2` | `gateway` | No | `fix_gateway_group.py` adds from tofu state |
| `asa` | `gateway01`, `gateway02` | **Yes** | None |

The gateway role is only invoked when `deployment_scope` includes `gateway` AND `gateway_release`
is set in `run-vars.yml`. The gateway group must exist in inventory either way — the Ansible
playbook hard-fails if its target group is missing.

**`tfvars-overrides/` gateway files are deprecated.** Older Themis branches (pre-2024) did not
include gateway VMs in their base tfvars. The override files in `tfvars-overrides/` were written
for those older branches. They are not applied by default. Set `DEPLOY_GATEWAY_TFVARS=true` in
`.env` to opt in (for old Themis checkouts only). The `asa-with-gateway.tfvars` override uses
the old dc1-/dc2-/dc3- naming and must never be applied against current Themis main.

## Architecture Auto-Detection

`generate_inventory.py` detects the design from instance names in Terraform state — no manual
input needed. Detection order: ASA → HA2 → Minimal → AIO. Detection is keyed to these
specific instance names:

| Design | Detection criterion |
|---|---|
| `asa` | All of: redis01–06, mongo01–05, platform01–04, gateway01–02 present |
| `ha2` | redis01–03, mongo01–03, platform01–02 present |
| `minimal` | `redis`, `mongo`, `platform` present |
| `aio` | `all` present |

## Known Infrastructure Gaps

These require manual edits to Themis's `terraform.tfvars` or are not supported by the
current Tofu variable schema. Use `.env` overrides for everything listed in the `.env`
schema — everything else is a manual-only gap.

| Gap | Workaround |
|---|---|
| All instances in one AZ (`default_subnet = public-1b`) | No per-instance subnet override in current Themis schema — all instances land in one AZ |
| AMI not pinnable (`most_recent` always used) | Environments may differ between runs as new AMIs publish; no `ami_id` variable exists |
| No IAM instance profile | Platform features needing EC2 metadata credentials are not supported |
| `root_volume_size` / `data_volume_size` | Schema supports per-instance, but no `.env` override exists — requires editing architecture tfvars directly |
| `associate_public_ip = false` | No `.env` override — private-subnet deployments require editing `terraform.tfvars` |
